# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Gemini, Cursor, …)
working in this repository. Humans: see [CONTRIBUTING.md](CONTRIBUTING.md).

## Project

`msi-gpu-for-icue` is a native Corsair iCUE 5 device plugin: a C++17 DLL
(`MsiGpuForIcue.dll`, MSVC, Windows x64 only) that drives the RGB controller of
MSI GeForce RTX 50 cards over NvAPI I2C. The iCUE plugin ABI is undocumented
and reverse-engineered.

Read before changing code:

- [docs/architecture.md](docs/architecture.md): modules, threads, life cycle
- [docs/protocol.md](docs/protocol.md): NvAPI I2C and controller registers
- [docs/icue-plugin-abi.md](docs/icue-plugin-abi.md): the iCUE plugin interface

## Layout

| Path | Content |
| --- | --- |
| `src/` | Plugin sources. Everything here is covered by the unit tests. |
| `tests/` | Unit tests, own mini framework (`test_framework.h`), fake NvAPI DLL (`fake_nvapi/`), installer end-to-end test (`e2e/`, CI only). |
| `installer/` | Inno Setup script for the setup.exe (wraps `install.ps1` / `uninstall.ps1`). |
| `tools/` | Manual hardware tools (`gputest`, `plugintest`) and the image generator. Not unit-tested. |
| `images/` | Device pictures per card style, `images/<style>/` (generated by `tools/make-images.ps1`). |
| `docs/` | Technical documentation. |
| `install.ps1`, `uninstall.ps1` | Installer (admin, certificate stores, Program Files). |
| `build.ps1`, `test.ps1`, `package.ps1` | Build, test/coverage, release zip and setup. |
| `renovate.json` | Dependency update PRs (GitHub Actions, CI tool versions); never auto-merged, they need a review. |

## Commands

All scripts are PowerShell. From the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1                 # build everything (/W4 /WX)
powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1                  # unit tests (~0.5 s)
powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1 -Filter Streamer # subset by name
powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1 -Coverage        # + 100 % line-coverage gate
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1               # dist\msi-gpu-for-icue-<version>.zip
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1 -Installer    # + dist\msi-gpu-for-icue-setup-<version>.exe
```

`-Coverage` needs OpenCppCoverage on PATH or `-OpenCppCoverage <path>`;
`-Installer` needs Inno Setup 6 (`ISCC.exe`) on PATH, in its default folder or
`-Iscc <path>`.
Requires Visual Studio 2022 or its Build Tools with the C++ workload.

## Definition of done

A change is complete only when all of these hold:

1. `build.ps1` succeeds with zero warnings (warnings are errors).
2. `test.ps1 -Coverage` passes: all tests green and **100 % line coverage of
   `src\`**. New code comes with tests; never lower the threshold, never
   exclude files, never add code that only exists to be covered.
3. Documentation matches the code (see "Keep in sync" below).
4. The commit message is a Conventional Commit (see below).

## Rules

### Safety

- **Do not run** `build\gputest.exe`, `build\plugintest.exe`, `install.ps1`,
  `uninstall.ps1`, a built `dist\*-setup-*.exe` or its uninstaller without the
  user's explicit consent in the current conversation. They drive real
  hardware, need administrator rights and change the machine's certificate
  stores.
- **Never run** `tests\e2e\installer.ps1` on a developer machine. It is meant
  for disposable CI runners and VMs only.
- Never change the `AppId` in `installer/msi-gpu-for-icue.iss`.
- **Never write register 0x3F** (save) or add code that persists lighting
  on the card.
- The unit tests must never load the real `nvapi64.dll`. Everything goes
  through `tests/fake_nvapi` via `nvi2c::SetLibraryName()`.
- Do not commit logs, `plugin.log` contents, build output or personal data.

### Compatibility

- The device id format `MSIGPU_<vendor><device>_<subvendor><subdevice>`
  (`device::DeviceIdFor`) is what iCUE stores user configuration under.
  Changing it is a breaking change (`feat!:`).
- LED ids must stay in the `0x30001 + n` range (`cue_abi::kLedGpuZone1`);
  other ids are rejected by iCUE.
- Settings keys in `settings.example.ini` are public API: renaming or removing
  one is a breaking change.
- No C++ exception may cross the exported ABI: every function iCUE calls
  wraps its body in `Guarded()` / `GuardedVoid()` from `src/abi_guard.h`.
  Memory handed to iCUE is freed only through our own `freeDeviceInfo` /
  `freeDeviceView`.

### Design

- Hardware access only through `nvapi_i2c`. Streaming timing goes through a
  `Clock`; anything that talks to the card takes a `LightDevice`. That is what
  keeps the code testable without hardware.
- Lock order: `lifecycle` → `announce` → plugin state → streamer → NvAPI
  (see docs/architecture.md). Only `announce` may be held while calling back
  into iCUE.
- C++17, 4 spaces, 120 columns, braces on their own line for functions.
  Comments explain *why*.

### Keep in sync

| When you change… | …also update |
| --- | --- |
| supported cards (`kKnownCards` in `src/msi_gpu.cpp`) | README table (incl. picture), `MsiGpu_DetectKnowsEveryListedCard` test |
| card pictures or styles (`tools/make-images.ps1`, `src/card_style.h`) | `kArt` in `src/device_description.cpp` (the script warns on a mismatch), README picture column |
| registers or sequences | `docs/protocol.md` and the sequence tests in `tests/test_msi_gpu.cpp` |
| ABI structures or exports | `docs/icue-plugin-abi.md` |
| settings keys or ranges | `settings.example.ini`, README settings table, `src/settings.h` |
| threads, life cycle, streaming rules | `docs/architecture.md` |
| code derived from another project | `THIRD_PARTY.md` (GPL-2.0-or-later compatible sources only) |

## Commits, versions, releases

- [Conventional Commits 1.0.0](https://www.conventionalcommits.org):
  `type(scope): description`, types `feat fix perf docs refactor test build ci
  chore style revert`, scopes `plugin streamer controller nvapi settings
  installer tools tests release`. `!` or a `BREAKING CHANGE:` footer for
  breaking changes.
- One logical change per commit.
- Versions follow SemVer and are **owned by release-please**: never edit
  `src/version.h`, `version.txt`, `CHANGELOG.md` or
  `.release-please-manifest.json` by hand.
- Enable the local hook once per clone: `git config core.hooksPath .githooks`.
- Do not push, tag or open releases unless the user asks for it.
